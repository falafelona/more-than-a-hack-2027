| D1 | 2026-10-22 | Match data lives **outside the repo**, located via `MTAH_DATA_DIR` | Keeps data out of git and away from AI tools; the organisers' `games.py` already uses `MTAH_DATA_DIR` | ✅ |
| D2 | 2026-10-22 | Derived frame-level files (caches, features) go under `$MTAH_DATA_DIR/cache/`, never in the repo | They count as data under the terms | ✅ |
| D3 | 2026-10-22 | Official challenge code comes in as a **pinned git submodule** at `vendor/challenge/`, never edited | Validator and metric stay identical to the official scorer | ✅ |
| D4 | 2026-10-22 | `CLAUDE.md`, `AGENTS.md` (symlink) and per-tool deny lists in the repo | Every agent gets the same data rules. They reduce risk but do not remove it (see D16) | ✅ |
| D7 | 2026-10-30 | Results are **one table** in `experiments/RESULTS.md`, aggregates only | Simple enough to keep up with; feeds the technical doc. Replaces one YAML per run | ✅ |
| D9 | 2026-10-30 | The public 5-minute GT **never chooses between versions**: no training, tuning or comparing by CI on it | It is a rule, and it picks the wrong model (`smooth125` over `smooth50`). One possession moves it by about 0.06 | ✅ |
| D10 | 2026-10-30 | Python 3.12, exact-pinned `requirements.txt`, pip. One command: `make submission` | Reproduction must give the identical file; pip needs no extra install | ✅ |
| D11 | 2026-10-30 | Results record dev-set scores on other matches, plus label-free stats on this match; no full-match score is claimed | We have no full-match ground truth before results day | ✅ |
| D13 | 2026-10-30 | The **H/A/D decoder is the core design**, and its main purpose is removing flicker. Dead ball is a score fed to it, not a hard override | spellF1 scores whole possessions; a false `D` splits one, so team and dead-ball decisions belong in one model | ✅ |
| D14 | 2026-11-15 | **No `X` is written** anywhere (`x_policy: none` in `final.yaml`); every frame gets `H`, `A` or `D` | Ungraded frames are never scored, so `X` or a label there gives the same score. On graded frames the scorer forward-fills `X` with our last label for spellF1, so `X` cannot gain, and it always counts as a miss for macroF1. Writing `X` on ungraded frames would only match the organisers' example file, for zero score change | ✅ |
| D15 | 2026-10-30 | All thresholds are **tuned on other matches**, starting with IDSSE | Hand labels and tuning on this match are banned, and organisers approved IDSSE (official issue #16) | ✅ |
| D16 | 2026-11-15 | Everyone keeps the match data on an **encrypted disk image, ejected while AI tools run** (`hdiutil detach /Volumes/mtah-data`) | Rules and ignore files only reduce risk; an unmounted disk cannot be read | ✅ |
| D17 | 2026-11-11 | The dev set takes its truth from IDSSE's own `BallStatus` and `BallPossession`, and its ball is **cut to look like ours**: gaps with the gap-length bins measured on our match (ball EDA), fixed seed, placed in **two ways**: `random` (anywhere) and `stoppage` (starting as the ball goes dead). Every comparison runs under both. IDSSE lives in `IDSSE_DATA_DIR`, outside the repo, and humans run `scripts/devset_eval.py` (`make devset`) | The provider's flag gives per-frame H/A/D without matching events, and IDSSE's ball is nearly complete while ours is missing about 41%. Our real gaps are a mix of open-play losses and stoppages, so the two placements bracket them. The flag and the simulated gaps are only approximations, so the dev score compares versions and does not predict the real one | ✅ |
| D18 | 2026-11-15 | **Go / No-Go, as we applied it:** every change is scored against the current `final.yaml` in four dev-set runs (random and stoppage gaps × seeds 0 and 1). It goes into `final.yaml` only if it is better in all four runs, on at least 6 of 7 matches in each. A mean gain of at least +0.04 spellF1 per run passes outright. A smaller gain goes in only by an explicit team decision recorded in `RESULTS.md` and here; that happened twice (D22, D24). Each change lands as its own small PR with tests, an experiment config, the paired tables and a `RESULTS.md` row, approved by a reviewer. If nothing passes, `final.yaml` stays as it is | With 7 dev matches, an average gain can come from one lucky match; requiring the gain in every run, on almost every match, keeps only changes that hold up. Differences under 0.04 on one run are inside the noise, so they need a second look by people | ✅ |
| D19 | 2026-11-15 | **Still-ball clue** in the dead score: a seen ball standing still (under 0.5 m/s for 2 s) at a restart spot (near a touchline or goal line, the centre spot or the goal area) adds 0.6 to the chance the ball is dead | It caught set-up restarts the other clues missed (dev set +0.066 / +0.033 on top of #45, 7/7). On our match the ball mostly vanishes during stoppages, so it fires far less (about 930 frames); expect a smaller gain there | ✅ |
| D20 | 2026-11-15 | **Restart rule:** when a dead spell of at least 3 s ends, the team nearest the ball around that moment takes the restart; the other team pays an extra cost for 2 s | Every restart has a clear possessor (CHALLENGE.md). With the still-ball clue it gives +0.080 / +0.042 over #45 on both seeds, 7/7. Its threshold (0.5) is coupled to the still-ball weight (0.6): a weight below 0.5 would switch the rule off after those stoppages | ✅ |
| D21 | 2026-11-15 | **No hand-labelling** of any part of our match, for any purpose: training, tuning or validation | Forbidden by the competition rules. All labels used for choosing settings come with the IDSSE dataset; the public 5 minutes are only a pipeline check (D9) | ✅ |
| D22 | 2026-11-16 | **Switch placement:** each H / A switch is placed 75% of the way into its no-evidence stretch (`possession.switch_placement: 0.75`), not on its first frame | Where no team has evidence, H and A cost the same, so Viterbi leaves the switch at the earliest frame; in reality possession changes when the ball arrives. Same total cost, same possessions, only the timing moves. Dev set +0.022 to +0.027: under the +0.04 of D18, but better on 7 of 7 matches in all four runs; approved by Abdallah and Tala (#49, #50) | ✅ |
| D23 | 2026-11-16 | **Touch evidence:** a sharp change of the ball's velocity next to one team's player (the other team's nearest player further away) gives that team strong evidence for 0.8 s (`possession.touch`) | The diagnosis (#55) showed the remaining misses are short spells of the other team that distance evidence cannot pay for; lowering the switch cost would add fakes. Dev set +0.055 to +0.060 in all four runs, 7/7. The settings were picked from 17 configs; the leave-one-match-out check gives the same gain (#57, #56, #58) | ✅ |
| D24 | 2026-11-16 | **Dead-score blend, by exception to D18:** inside a ball gap the dead score is `gap_chance` × 0.3 + the learned score × 0.7 (`learned_dead.py`, model `models/deadball_stoppage_all.json`, fitted on stoppage gaps of all 7 IDSSE matches). This is `final.yaml` at tag `v1.2` | Against the touch final it gains +0.040 / +0.023 / +0.037 / +0.022 (seed 0 random / stoppage, seed 1 random / stoppage) and is better on 27 of 28 match-runs (worst match -0.005). That fails the +0.04 of D18 under stoppage gaps, where even a perfect dead call inside gaps is worth only +0.041 (oracle, #55). Tala took the exception and the team agreed. Known cost: it was chosen from about 8 variants on the same 7 matches, so part of its lead may be luck. Fallback kept: the touch final, sha256 `850cc01c…f2f9aa68` (#54, #59, #60) | ✅ |
| D25 | 2026-11-16 | **Anything fitted or picked on the dev set is checked leave-one-match-out.** On the dev set each match is scored with a model fitted on the other six (`models/deadball_stoppage_lomo_<match>.json`, the twin config `configs/exp/poss-blend-learned70-stopmodel.yaml`); only the submission uses the model fitted on all seven. A config picked from a sweep is checked with `scripts/touch_lomo.py` | A model scored on a match it was fitted on, or a config picked on the matches it is scored on, flatters the dev score. The dev-set reference for `v1.2` is the twin config, not `final.yaml` | ✅ |
